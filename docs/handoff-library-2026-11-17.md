# 라이브러리 답변 자료 — 저장 (2026-11-17)

GA4·Amplitude를 먼저 하려고, 라이브러리 답변 자료 작업을 여기서 멈추고 상태를 남긴다.

## 목적

라이브러리(`/library`)의 AI는 아클링스가 준비한 답변 자료 안에서만 답한다.
답변 자료는 아키텍터가 책 원문을 NotebookLM에 올려 받은 정리 답변이다. NotebookLM을 쓰는 이유는 올린 자료 밖의 지식을 섞지 않기 때문이다.
할 일은 라이브러리의 넓은 질문 121개(`docs/library-questions-source-2026-11-07.md`)와 답변 자료를 묶는 것이다. 질문마다 답, 이어 물을 질문과 답, 머리말(태그·속성·짧은 요약)을 한 파일에 쓰고 분류 폴더에 넣는다.
근거 번호는 아키텍터가 NotebookLM 안에서 원문을 확인하는 용도다. 고객에게 원문이나 근거 번호를 보여 줄 일은 없다.

| 작업 폴더 | 볼트 맨 위 `_작업_라이브러리답변/` — `작성규칙.md`(형식·머리말·책 사이 불일치 11가지), `질문목록.md`(121문항 진행 상태·들어갈 폴더·장마다 읽을 정리본), `찾기.py`(정리본 낱말 검색) |

| 아키텍터 확인 대기 | 질문별 들어갈 폴더(임시로 정함), 1장 파일 내용 |

규칙: 장 단위로 정리본을 한 번 읽고, 그 장 질문을 다 쓴 뒤 보고하고 확인받는다. 장 순서를 건너뛰지 않는다.

### 2. Fable 5.2 세션 「Brief-fable 문서 작업」 (클라우드)

결과는 살려 둔다. 질문과 답을 묶은 것은 아니고, 자료 운영 설계를 제안했다.
세 문서 초안이 그 세션의 임시 폴더에만 있다(저장소에 못 넣음 — 범위 잠금 훅과 Claude Code 자동 권한 검사 충돌, 티켓 003으로 고침).

- `format.md`: 표본에서 찾은 문제 17가지, 파일 틀, 질문 121개↔분류 폴더 대응표, DB 연결, 원문 색인 틀
- `exemplar.md`: Q03-05 「나라는 어떻게 무너져요?」 본보기(비공개)
- `writer-guide.md`: 작성 지침

쓸 만한 판단:
- 질문마다 고정 번호를 붙이면 파일·DB 줄이 이어진다.
- 한 파일을 「질문 하나 + 답 하나」 묶음으로 나누면, 지금 검색(낱말 겹침으로 3줄 고르기)이 더 정확한 줄을 고른다.
- 지금 `lib/wiki.ts`는 공개 줄을 200개까지만 읽는다. 자료를 다 넣으면 넘친 줄이 오류 없이 빠진다. 넣기 전에 한도를 올려야 한다.
- 표본 06(외교)과 07(전쟁) 본문이 거의 같다. 06에 외교 내용이 없다.
