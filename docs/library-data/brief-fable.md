# 라이브러리 자료 틀 결정 — Fable 작업 지시

## 목적

아클링스 라이브러리(`/library`)의 AI 질의응답이 쓸 자료 파일의 **틀과 분류 규칙**을 정한다.
아키텍터는 이 틀을 기준으로 남은 자료를 정리하고, 이후 Opus·Sonnet이 나머지 파일을 이 틀대로 쓴다.
그래서 이 결정이 뒤의 파일 100여 개 전체의 품질을 정한다.

## 판단 기준

기존 기능을 망가뜨리지 않는 선에서 다음 셋을 모두 높이는 최선의 결정을 내린다.

| 기준 | 뜻 |
|---|---|
| UX (사용자 경험) | 라이브러리에서 질문한 사람이 정확하고, 근거가 보이고, 이어서 물을 거리가 있는 답을 받는다 |
| DX (개발자 경험) | 파일을 DB에 넣는 일이 단순하고, 틀이 바뀌어도 코드를 크게 고치지 않는다 |
| AX (에이전트 경험) | 뒤에 쓰는 모델이 이 틀만 보고 헷갈리지 않고 같은 품질로 쓴다. 색인으로 관련 원문만 골라 읽을 수 있다 |

## 지금 있는 것

| 것 | 위치 |
|---|---|
| 기존 표본 10개 (아키텍터가 만든 것, `고조선왕조실록_이희진` 기반) | `docs/library-data/samples/` |
| 라이브러리 넓은 질문 121개 (15묶음) | `docs/library-questions-source-2026-11-07.md`, 화면용 `lib/library-questions.ts` |
| 자료를 읽는 코드 | `lib/wiki.ts` — 표 `library_wiki`의 `id, question, answer, source, era`를 공개분만 최대 200개 읽고, 질문 낱말로 최대 3개를 고른다 |
| 질의응답 처리 | `lib/ai/library-handler.ts` |
| 맥의 분류 폴더 | `아클링스볼트/분류/` 13개 (`01_제국의탄생과몰락` … `13_무속과이적`) + `_미분류` |
| 맥의 원문 자료 | `아클링스볼트/LM_세계관 분류/` 책 6종, 약 85개 파일, 약 70만 자. 그 밖에도 자료가 더 있다 |

## 기존 표본에서 아키텍터가 원하는 것

- 넓은 질문 하나에 대한 답을 원문 자료로 쓴다.
- 사용자가 이어서 물을 질문을 예상해 그 답도 같은 파일에 쓴다.
- 머리말에 태그, 속성, 짧은 요약을 둔다.
- 파일을 `분류` 폴더에 나눠 넣는다.

기존 표본은 출발점일 뿐이다. 더 나은 틀이 있으면 그것을 제시한다.

## 할 일

1. 표본 10개, 질문 121개, `lib/wiki.ts`를 읽는다.
2. 표본의 문제를 찾는다. (예: 06과 07 본문이 거의 같다. 머리말의 `나라`가 본문과 어긋난다. 근거 쪽수가 없다.)
3. 파일 틀을 정한다. 머리말 칸 각각의 이름, 뜻, 값 규칙, 필요한 이유를 적는다.
4. 분류 규칙을 정한다. 질문 121개의 15묶음과 분류 폴더 13개의 대응표, 한 파일이 여러 곳에 걸칠 때의 규칙을 적는다.
5. 파일과 DB의 연결을 정한다. 지금 `library_wiki` 칸으로 충분한지, 바꿔야 하면 무엇을 바꿔야 하는지 적는다. 코드와 DB는 고치지 않는다.
6. 원문 색인의 틀을 정한다. 뒤 모델이 70만 자를 한 번만 읽고 색인을 남긴 뒤, 질문마다 관련 원문만 읽게 하기 위한 것이다.
7. 본보기 파일 하나를 완성한다. 표본 하나를 골라 새 틀로 다시 쓴다. 근거는 표본 본문 안에서만 쓴다.
8. 뒤 모델에게 줄 작성 지침을 쓴다. 해야 할 일을 긍정문으로 쓴다.

## 지킬 것

- 코드, DB, 화면은 바꾸지 않는다. 문서만 만든다.
- 결과는 `docs/library-data/` 안에 쓴다: `format.md`(틀·분류·DB 연결·색인), `exemplar.md`(본보기), `writer-guide.md`(작성 지침).
- 아키텍터가 정한 것과 Fable이 새로 제안한 것을 구분해 적는다.
- 끝나면 `dev`에 올리고, 결정 요약을 표로 보고한다.
