## 작업 규칙 (별뜨리님이 여러 번 강조함)
1. **질문에는 답만 한다. 고치라고 하지 않으면 파일을 고치지 않는다.** 말하지 않은 것을 고치지 않는다(이 때문에 크게 꾸중 들음). 되돌릴 일이 생기면 먼저 묻는다.
2. 요청한 곳만 고친다. 다른 것을 건드리기 전에 먼저 말한다.
3. 화면은 `public/landing.html`의 디자인 시스템(색·글꼴·버튼·카드·여백)을 따른다. 기본 배경색은 `#FAF7F8` 그대로(얼룩·그라데이션 금지). 카드에 외곽선 없음. 자주색(primary)은 핵심 버튼 위주, 강조는 청록 등.
4. 크리에이터 화면 위쪽은 제목+설명만 두고 제목 위 작은 글(kicker)은 없다. 오류·404 화면은 제목을 둔다. 설명·안내 문구는 별뜨리님이 지시한 것만 둔다(군더더기 설명 싫어함).
5. 시안(Figma 2장: 「크리에이터 포트폴리오 탐색」, 「크리에이터 프로필」)은 배치 뼈대로만 쓴다. 시안에 없는 화면은 **코드 전에 배치도로 승인**받는다(7단계는 승인 끝). 화면마다 "시안에 있던 것/달라진 것/새로 만든 것"을 나눠 보고한다.
6. 한 단계씩 샘플 미리보기(`/dev-preview/...`)로 1440·375에서 보여 주고 승인받은 뒤 다음으로. 매 단계 끝에 `npm run lint`, 계획 문서 갱신, **`design` 가지에 커밋·푸시**(커밋 끝에 `Co-Authored-By: 그 세션의 모델 이름 <noreply@anthropic.com>`). `dev`·`main` 병합/푸시는 별뜨리님이 시킬 때만.
7. 보고는 개발 용어를 쉽게 풀어서, 끝에 남은 위험/한계를 적는다. 직접 확인 못 한 것은 확인 못 했다고 말한다. 확인 못 한 것을 한 것처럼 말하지 않는다.
8. 파일 삭제는 훅이 막는다. 지울 파일과 이유를 먼저 설명하고 허락받는다(예: 마지막에 지울 샘플 미리보기 주소). 새 폴더도 만들기 전에 이유부터 말한다.
9. 새 패키지·외부 서비스 연결·환경 변수 추가는 승인 필요. 백엔드는 **크리에이터 데이터에 한해** 허용(`app/actions`, `lib`의 크리에이터 관련 파일, 새 SQL 파일). 로그인·가입·탈퇴 등 다른 백엔드, `proxy.ts`, `app/api`, `app/auth/callback`, 0001~0007은 건드리지 않는다. 협업 신청은 "받는 사람을 크리에이터로 정하는 길 추가"만 허용, 협업 신청 화면 디자인은 그대로.
10. 크리에이터 관련 화면 말고 다른 화면의 디자인은 아무것도 건드리지 않는다. 다른 화면에서는 크리에이터 화면과 이어지는 부분만 작동하게 고친다.

## 구조 결정 (별뜨리님, 계획 문서 0번)
- 크리에이터 목록/프로필은 콘텐츠와 같은 급의 독립 메뉴. 기획안 없이도 프로필을 만들 수 있다(마이페이지에서 따로, 또는 기획안 처음 공개할 때).
- D2: 옛 /portfolio 목록 주소는 /creators로 보내고, /portfolio/<id> 상세 주소는 그대로 둔다.
- 포트폴리오 = 공개한 기획안 + 「작업물 링크」(제목·짧은 설명(100자)·링크·역할 표시(6개 중 하나), 사람당 30건, 사진·파일 올리기 없음). 참여작은 이번에 제외.
- 프로필 공개/비공개: 마이페이지에서 만들면 기본 비공개(직접 공개로), 기획안 올리며 만들면 그 자리에서 공개. 목록·프로필 주소에는 공개 프로필만. 비공개 프로필 주소는 남에게 404, **본인에게는 「비공개 상태입니다」 표시와 함께 보임**(D13).
- D12: 비공개 프로필 보유자가 「포트폴리오에 올리기」를 누르면 「프로필도 공개할까요?」를 한 번 묻고, 어느 쪽이든 기획안은 공개. 프로필을 비공개로 돌려도 공개한 기획안은 그대로, 기획안 상세에는 작성자 이름만(프로필 링크 없음).
- 프로필 화면에 「이 크리에이터에게 협업 신청」(받는 사람=그 크리에이터, `/collab/new?creator=<공개주소>`). 협업 가능 끔·비공개 미리 보기에서는 버튼 숨김. 크리에이터 0명일 때 안내는 「기획안 만들기」(→/planner)와 「크리에이터 프로필 만들기」(→/mypage) 둘 다.
- 새 데이터 확정: P1 역할별 한 줄(60자), P2 소개 글(500자), P3 채널 링크(5개, https만), P5 링크의 대표 이미지 주소(https만, 안 열리면 역할 카드), P6 협업 가능(기본 **켜짐**, D16). P4 대표 작업 고정은 미룸. 썸네일 우선순위: 대표 이미지 주소 → 유튜브 썸네일(영상 번호로 주소 생성) → 역할 표시 카드.
- 공개 주소(public handle)는 크리에이터가 직접 짓는다. 한 번 정하면 못 바꿈. 중복 확인(버튼+자동)이 있고 이미 쓰는 주소는 저장 안 됨. 부적절한 단어 차단·신고·운영자 숨김은 이번 범위 밖(위험에 "실제 운영 전 필요"로 기록).
- `/privacy`는 이번에 고치지 않는다. 위험에 적을 것: 유튜브·외부 이미지를 방문자 브라우저가 직접 받아 옴 → "실제 운영 전 /privacy(와 P5는 운영자 숨김 기능)에 함께 다룰 것".
