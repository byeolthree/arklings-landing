# 미리보기 클릭 확인표 (dev 브랜치)

미리보기 주소: https://arklings-main-deploy-git-dev-chongaaa19-7825s-projects.vercel.app
(Vercel 로그인 보호가 걸려 있으면 Vercel에 로그인한 브라우저에서 여세요.)

## 확인된 사실 (아키텍터 확인, 이 표의 전제)

1. Vercel 환경변수 `NEXT_PUBLIC_SUPABASE_URL`·`ANON_KEY`는 development·preview·production에 같은 값이 걸려 있다. **미리보기와 production은 같은 Supabase DB를 쓴다.** 그래서 미리보기에서 가입·신청·탈퇴를 누르면 **진짜 production 데이터가 바뀐다.** 시험은 가짜 이메일·가짜 값으로만 한다.
2. DB: `profiles`(0002)는 있다. `admins`(0003), `plans`·`plan_revisions`(0004), `cleanup_runs`(0005)는 없다. 0006은 확인 안 했다. 0007(`portfolio_items`)은 없다(미리보기 `/portfolio`가 서버 오류로 확인됨).
3. 같은 DB라서 0003부터 실행하면 production의 예전 협업 신청이 멈춘다. **SQL 실행과 `main` 배포는 아키텍터가 정한다.** 이 문서는 SQL 실행을 안내하지 않는다.
4. Supabase의 「Allow manual linking」은 꺼져 있다.

그래서 지금 미리보기에서 진짜로 눌러 볼 수 있는 것은 DB 필요가 「없음」·「0002」인 줄뿐이다. 아래 표의 마지막 칸이 그 판단이다.

## 미리보기에서 안 되는 것의 이유 한눈에

| 안 되는 것 | 이유 |
|---|---|
| `/portfolio`, `/portfolio/번호`, 기획안으로 협업 신청 | `portfolio_items`(0007) 없음 |
| 기획안 저장·이력·공개·메일 받기, 마이페이지의 내 기획안 목록 | `plans`·`plan_revisions`(0004) 없음 |
| 협업 신청 접수, 받은 협업 신청 목록·상세·수정, 회원 탈퇴 실행 | 받는 사람 칸·`admins`·`submit_attempts`(0003) 없음 |
| 소셜 계정 이어붙이기·마이페이지 연결/해제 | Supabase 「Allow manual linking」 꺼짐 |
| 카카오에서 이미 쓰는 이메일을 입력하는 흐름 | 0006 적용 여부 미확인 |
| 가입·재설정 메일의 링크 도착 | Supabase 메일·이메일 템플릿·Redirect URLs 설정 확인 필요(미확인) |
