# 아클링스 (미션 7)

한국 신화·고대사 기반 IP 스튜디오 **아클링스**의 랜딩 페이지, 기획안 만들기, 로그인, 협업 신청, 포트폴리오입니다.
Next.js(App Router, Server Actions) + Supabase(DB·Storage·로그인) + Vercel.

- 배포 주소: https://arklings-main-deploy.vercel.app
- 저장소: https://github.com/byeolthree/arklings-landing
- 작업 규칙과 자세한 구조: [`AGENTS.md`](AGENTS.md)

## 화면

| 화면 | 주소 | 하는 일 |
|---|---|---|
| 랜딩 | `/` | v14 랜딩. 「지금 시작하기」(5곳) → 기획안 만들기(`/planner`), 「협업 문의하기」(2곳) → 협업 신청(`/collab/new`) |
| 기획안 만들기 | `/planner` | 로그인 없이 작성(이 기기 브라우저에만 보관). 로그인하면 서버 저장·임시저장 이력·Ctrl+Z·PDF 내려받기·PDF 메일 받기(하루 3번)·포트폴리오 공개. 옛 주소 `/planner.html`은 여기로 이동 |
| 포트폴리오 | `/portfolio`, `/portfolio/[id]` | 공개된 기획안만 누구나 보기. 공개 이름은 보이고 이메일은 보이지 않음. 상세의 「협업 신청」은 기획안 주인에게 감 |
| 로그인 | `/signup`, `/login`, `/forgot-password`, `/reset-password` | 이메일·구글·카카오 로그인. 카카오처럼 이메일을 주지 않는 방식은 가입 중에 이메일을 받아 확인 메일로 본인 확인(`/auth/add-email`) |
| 마이페이지 | `/mypage`, `/mypage/withdraw` | 내 기획안 목록, 로그인 방법 추가·해제, 회원 탈퇴 |
| 협업 신청 | `/collab/new` | 누구나 로그인 없이 접수 (`/apply`는 여기로 이동) |

| 받은 협업 신청 | `/collab`, `/collab/[id]`, `/collab/[id]/edit` | 로그인 필요. 그 신청을 받은 사람만 목록·상세·수정·삭제. 10개씩, 상태별 보기 |
| 개인정보처리방침 | `/privacy` | 가입·협업 신청과 같은 동의 문구 |

**협업 신청 입력 칸:** 이름/닉네임(필수), 연락처 이메일 또는 전화번호(필수), SNS 아이디(필수), 신청 대상(기본 "특정 이야기 아님", 또는 작품 선택. 포트폴리오에서 들어오면 작품 칸 대신 기획안 제목과 「○○님께 전달됩니다」), 역할(중복 선택, 1개 이상 필수: 영상 제작·대본·아트디렉터·역사 자문·책임 프로듀서·기타), 하고 싶은 일/아이디어(필수, 10~1000자), 작업 링크(필수, http/https), 작업 파일 첨부(선택, PDF·JPG·PNG 4MB 이하. 더 큰 파일은 작업 링크로), 개인정보 동의(필수), 상태(받는 사람이 수정할 때만: 접수·검토 중·수락·거절).

**성공/실패:** 신청하면 접수 완료 화면으로 이동합니다. 입력 오류는 칸 아래에 이유를 보여 주고 입력값을 유지합니다. 저장 중에는 버튼이 잠깁니다. 삭제는 확인 후 신청과 첨부 파일을 함께 지웁니다. 없는 번호나 남에게 온 신청은 404 화면이 나옵니다.

**접근 규칙:** 받은 협업 신청은 받는 사람만 읽고 고치고 지웁니다(DB 접근 규칙 RLS). 아클링스 앞 신청은 운영자 표시가 있는 계정이 봅니다. 첨부 보관함은 비공개이고, 받는 사람에게만 5분짜리 임시 주소로 보여 줍니다.

## AI 기능 (미션7-2)

자세한 기준과 결정 기록은 [`docs/mission7-2-llm-plan.md`](docs/mission7-2-llm-plan.md)에 있습니다.

### 선택한 기능과 선택 이유

- 일반 GPT에 한국 고대사 이야기를 물으면 아클링스가 쓰지 않는 시대·설정이 섞입니다. 그래서 **아클링스의 질문 기준과 아클링스의 자료 안에서만** 점검받고 답을 얻는 기능 두 가지를 만들었습니다.
- 시대는 열국시대~삼한일통기로 고정합니다. 자료에 없는 연도·인물·궁궐·숫자는 지어내지 않고 「확인이 필요해요」 또는 「이 자료에는 없는 내용이에요」로 답합니다.
- 모델은 부트캠프가 지정한 OpenAI입니다. 지금은 작동 시험 단계라 가장 싼 모델을 씁니다(모델 이름은 환경변수 `OPENAI_MODEL`).

### 두 기능

| 기능 | 위치 | 하는 일 |
|---|---|---|
| AI 평가 | `/planner` 로그라인 화면의 「평가 받기」 | 다섯 칸(사건·주인공·장애물·목표·위험)을 기준 문항(`components/planner/questions.ts`)에 따라 칸마다 「충족 / 보완 필요」, 이유 1~2문장, 고칠 점(질문 한 문장)으로 점검합니다. 평가는 의견만 줍니다. 사용자의 글을 바꾸지 않고 저장·공개도 대신하지 않습니다. 결과는 본인만 읽는 별도 표(`plan_evaluations`)에 남습니다 |
| 라이브러리 질의응답 | 상단 메뉴 「라이브러리」(`/library`) | 위쪽에 게시된 질문과 답(위키에서 공개로 켠 항목, 누구나 봄), 아래쪽에 질문 칸이 있습니다. 서버가 위키(`library_wiki` 표)에서 질문과 가까운 항목을 고르고, AI는 그 항목 안에서만 답을 조금씩 보여 줍니다(스트리밍). 답 아래 「근거 자료」 이름은 AI가 쓴 글이 아니라 서버가 고른 항목에서 읽어 붙입니다 |

두 기능 모두 로그인하고 이메일 확인을 마친 사람만 씁니다. 일반 계정은 기능마다 하루(한국 날짜) 10번, 운영자 계정은 1000번입니다.

### 사용법 (데모 순서)

1. `/login`에서 로그인합니다(이메일 확인을 마친 계정).
2. `/planner`에서 로그라인 다섯 칸을 모두 채웁니다. 빈 칸이 있으면 「평가 받기」가 꺼지고 이유가 보입니다.
3. 「평가 받기」를 누릅니다. 「기준에 맞춰 읽는 중이에요」가 보인 뒤 칸별 결과가 나옵니다. 단추 옆에 「오늘 남은 평가 ○번」이 보입니다.
4. 상단 메뉴 「라이브러리」로 가서 게시된 질문과 답을 읽고, 질문 칸에 묻습니다. 답 아래에 근거 자료 이름이 보입니다. 자료에 없는 것을 물으면 「이 자료에는 없는 내용이에요.」가 나옵니다.

### 기술 선택 이유

| 선택 | 이유 |
|---|---|
| AI SDK(`ai`, `@ai-sdk/openai`, `@ai-sdk/react`) | 공급자·모델이 바뀌어도 코드를 거의 고치지 않습니다. 공급자를 고르는 곳은 `lib/ai/model.ts` 한 파일입니다 |
| 평가는 Server Action, 질의응답은 Route Handler | 평가는 한 번에 끝나는 생성(`generateText` + `Output.object`)이라 프로젝트 관례인 Server Action(요청 출처 검사가 기본으로 붙음)을 씁니다. 질의응답은 답을 조금씩 보여 주는 스트리밍(`streamText` + `useChat`)이라 정해진 주소로 요청을 받는 Route Handler(`app/api/library/ask`)를 쓰고, 출처(`Origin`) 검사를 직접 넣었습니다 |
| 하루 횟수 제한(DB 함수) | 모델을 부르기 직전에 DB 함수 `reserve_ai_use` 한 번으로 「확인과 증가」를 함께 합니다. 동시에 여러 번 눌러도 횟수가 새지 않습니다. 호출이 실패하면 `release_ai_use`로 자리를 돌려줍니다 |
| Supabase 위키 표 | 공개로 켠 항목만 DB 읽기 규칙(RLS: 줄 단위 접근 규칙)이 열어 줍니다. 쓰기 규칙은 없고 항목은 Supabase 화면에서 넣습니다. AI 기능에는 서버 전용 열쇠를 쓰지 않습니다 |
| 결과 모양 검사(Zod) | 평가 결과는 모양을 고정한 JSON으로 받고, 서버가 칸 이름·순서·길이를 다시 검사합니다(`lib/ai/evaluation-schema.ts`). 화면에는 글자로만 보입니다 |

**단순하게 만든 부분과 장단점**

- 위키 항목 고르기는 질문과 항목의 낱말이 겹치는지로 합니다(`lib/wiki.ts`). 장점: 검색 장치 없이 바로 동작하고 비용이 없습니다. 단점: 비슷한 뜻의 다른 낱말은 찾지 못합니다. 위키가 커지면 검색 방식(RAG)으로 바꿉니다.
- 관련 항목이 없으면 모델을 부르지 않고 횟수도 줄지 않습니다. 장점: 비용이 들지 않습니다. 단점: 낱말이 안 겹치면 자료에 있는 내용도 「없음」으로 나올 수 있습니다.
- 재시도는 하지 않습니다(`maxRetries: 0`). 자동 재시도도 비용이기 때문입니다. 시간 상한은 평가 30초, 질의응답 40초입니다.
- 모델 역할 지침은 서버 파일(`lib/prompts/`)에만 둡니다. 사용자 글은 「자료」로 감싸 넘기고, 그 안의 지시(「앞선 지침을 무시하고…」 등)는 따르지 않게 했습니다. 화면이 보낸 `system` 역할 메시지는 거절합니다.

### 실패했을 때 화면 안내

| 상황 | 화면에 보이는 것 |
|---|---|
| 로그인 안 함 | 로그인 안내(로그인 뒤 같은 화면으로 돌아옴). 모델을 부르지 않습니다 |
| 빈 칸 있음(평가) | 버튼 꺼짐과 「비어 있는 칸: ○○」 |
| 하루 횟수를 다 씀 | 「오늘 쓸 수 있는 평가(질문)를 모두 썼어요」. 쓰신 글은 그대로입니다 |
| 키 없음·잘못됨·잔액 한도 초과 | 「AI와 연결하지 못했어요」. 내부 오류와 키는 보이지 않습니다 |
| 요청 몰림(429) | 「지금 요청이 몰려 있어요」와 다시 시도 |
| 일시 오류·시간 초과(평가) | 「평가를 마치지 못했어요」와 다시 시도 |
| 결과 모양이 틀림(평가) | 「결과를 화면에 보여 드리지 못했어요」와 다시 시도 |
| 위 오류가 났을 때 횟수 | 「오늘 횟수는 줄지 않았어요.」(잡은 자리를 돌려줍니다) |
| 위키에 관련 항목 없음 | 「이 자료에는 없는 내용이에요.」 |
| 답이 도중에 끊김 | 「답변을 마치지 못했어요」와 원래 질문 유지. 완성된 답처럼 보이지 않게 합니다 |

### 환경변수 (이름만)

- `OPENAI_API_KEY`, `OPENAI_MODEL`: 둘 다 있어야 진짜 모델을 씁니다. 서버에서만 읽습니다(`NEXT_PUBLIC_`을 붙이지 않음).
- `AI_FAKE_MODEL`: 값이 `1`이면 OpenAI를 부르지 않고 정해진 시험용 답으로 연결·오류·형식 경로만 확인합니다(비용 0). 실제 사이트(production)에서는 켜져 있어도 쓰지 않습니다. 가짜 모델의 성공은 진짜 모델 품질의 증거가 아닙니다.

### 확장 가능성

- **다른 페이지 평가:** 평가 기준은 페이지(섹션) 단위로 갈아 끼웁니다(`EVAL_SECTION`). 로그라인 다음 페이지가 생기면 기준 문항과 프롬프트만 더합니다.
- **크레딧:** 횟수는 DB 함수 `ai_daily_limit()` 한 곳에서 정하고, 화면 문구는 `components/ai/usage-text.ts` 한 곳에 있습니다. 크레딧 방식은 결제(미션 11)를 만들 때 다시 정합니다.
- **검색 방식(RAG):** 위키가 커지면 `lib/wiki.ts`의 항목 고르기를 검색 방식으로 바꿉니다.
- **모델 교체:** 절차는 [`docs/model-swap.md`](docs/model-swap.md)에 있습니다.

## 테이블 구조

## 실행 방법

1. **새 Supabase 프로젝트:** SQL Editor에서 `supabase/schema.sql`을 실행한 뒤 `supabase/migrations/`를 `0001`부터 `0007`까지 번호 순서대로 실행합니다.
   **이미 운영 중인 프로젝트:** `schema.sql`은 `collab_requests`를 지우므로 다시 실행하지 않습니다. `migrations`만 번호 순서대로 실행하고, `0001`과 `0003`부터는 새 코드를 배포하고 `SUPABASE_SERVICE_ROLE_KEY`를 넣은 뒤에 실행합니다.
2. `.env.example`을 `.env.local`로 복사해 값을 채웁니다.
3. `npm install` → `npm run dev` → http://localhost:3000
